# Client export template specification

Status: implemented for the local candidate. The template package,
deterministic layout preflight, professional XLSX and HTML/PDF renderers,
explicit current/saved transaction, and export-center UI are present. PDF
generation still requires its documented optional local runtime.

Template ID: `client-storyboard`

Initial version: `1.0.0`

## Purpose

Provide a professional, brand-neutral client package that can be generated repeatedly from validated project data without manual page-by-page formatting.

The template owns presentation only. It cannot invent missing VO, identify speakers, infer source stems as fact, or change measured timing.

## Invocation and storage

The template runs only after an explicit Generate action from the UI, CLI, or an authorized Codex operation. Normal analysis and Finalize do not render client files.

Default outputs replace one stable slot atomically:

```text
reports/client/current/client_breakdown.xlsx
reports/client/current/client_breakdown.pdf
reports/client/current/export_receipt.json
```

No timestamped copy is created by default. **Save as version** creates a deliberate immutable snapshot below `reports/client/saved/<version-id>/`. Print HTML and partial render output remain in a private staging directory and are deleted on success or failure.

## Template package

```text
src/video_analysis_mvp/templates/client/
├── manifest.json
├── design_tokens.json
├── layout.json
└── assets/
    └── README.md
```

`src/video_analysis_mvp/export_templates.py` loads the package, verifies the
pinned asset hashes for version `1.0.0`, validates bounded branding settings,
and produces a deterministic layout plan without writing XLSX or PDF files.
The HTML/CSS print surface is generated by the PDF adapter from the same
validated dataset and layout plan. It remains renderer-owned rather than a
second template or truth source.

`src/video_analysis_mvp/export_xlsx.py` is the generation-only spreadsheet
adapter. It consumes the same validated dataset and preflight plan, requires the
optional `export` dependency, writes one new caller-supplied staging path and
returns a byte-bound structural receipt. It does not replace the current client
package, update the artifact registry, Finalize a project or run automatically.

The manifest contains:

- template ID and semantic version;
- compatible export-dataset schema versions;
- required sheets and PDF sections;
- default language and density;
- font-pack requirements and hashes;
- design-token hash;
- renderer compatibility;
- migration notes.

Changing layout, typography, column contracts, or pagination rules requires a new template version. Receipts bind the exact version and asset hashes.

## Design principles

- client-readable before information-dense;
- one visual hierarchy across Excel, HTML, and PDF;
- neutral enough for general use, with optional logo and accent-color settings;
- no project-specific names, claims, or private paths in template files;
- uncertainty visible but not visually overwhelming;
- measured, estimated, interpreted, and human-reviewed content use distinct labels;
- automatic pagination instead of shrinking text below the readability floor;
- no clipped text, stretched frames, orphan headings, or single-row final pages.

## Design tokens

### Color

| Token | Default | Use |
| --- | --- | --- |
| `ink` | `#111827` | primary text |
| `navy` | `#0B1020` | covers and section headers |
| `accent` | `#2E7DFF` | hierarchy and active status |
| `teal` | `#237A70` | verified/evidence accent |
| `paper` | `#F7F9FC` | alternate rows and panels |
| `line` | `#D6DDEA` | table borders |
| `muted` | `#667085` | metadata and limitations |
| `warning` | `#8A5600` | unverified/stale notices |

User branding may replace `accent` and add a logo. Contrast must still pass the template checks.

### Typography

- PDF uses a pinned, redistributable CJK-capable font pack installed during explicit export setup and embedded into the PDF.
- Excel declares the configured CJK font and records it in the export receipt; spreadsheet applications may substitute it, so layout tests include Excel-compatible and LibreOffice rendering.
- cover title: 24–30 pt;
- section title: 15–18 pt;
- table header: 9–10 pt semibold;
- body: 9–10 pt;
- metadata: minimum 8.5 pt;
- no automatic path may reduce text below 8.5 pt.

Long content continues into another row or page instead of being clipped or indefinitely shrinking.

### Spacing

- base unit: 4 mm for PDF and 4 logical units for workbook layout calculations;
- page safe area: minimum 12 mm;
- table cell padding: minimum 2.5 mm;
- image/text gap: minimum 4 mm;
- section gap: 8–12 mm.

## Excel contract

### Workbook metadata

- title, subject, creator, template ID/version, export ID, generation time, and project ID;
- freeze panes and filters on data sheets;
- repeated print headers;
- defined print areas;
- landscape orientation for storyboard and audio sheets;
- no formulas generated from untrusted input;
- workbook calculation mode does not require macros;
- no VBA, external links, hidden tracking sheets, or remote images.

### Sheets

#### `01_项目概览`

- title and optional client/project subtitle;
- core proposition or analysis objective;
- runtime, shot count, narrative-section count, transcript count, and export status;
- narrative structure summary;
- evidence/interpretation legend;
- current limitations and missing optional engines.

#### `02_逐镜分镜表`

Columns:

1. shot number;
2. narrative section;
3. timecode;
4. duration;
5. embedded frame;
6. visual description;
7. VO/dialogue;
8. on-screen text;
9. music/SFX;
10. rhythm/transition;
11. verification status.

Rules:

- every current shot appears exactly once;
- frames preserve aspect ratio and use letterboxing rather than distortion;
- missing frames use a bounded placeholder with evidence status;
- row height is calculated from image height and wrapped-text line estimate;
- text exceeding the maximum row height continues in a linked continuation row;
- section changes receive a restrained separator, not a full-page decorative break;
- filters, frozen identity columns, and repeatable print headers remain usable with hundreds of shots.

#### `03_VO与画面文字`

- ordered by timecode;
- separates ASR text, reviewed wording, on-screen text, anonymous speaker, and voice-role estimate;
- includes confidence and source without exposing internal debug payloads;
- uses explicit blank/unknown cells instead of filler copy.

#### `04_音乐与节奏`

- narrative sections and music cues;
- energy arc, estimated tempo, silence, SFX events, cut/rhythm relationship, and client-facing interpretation;
- one bounded waveform/energy visualization generated from current evidence;
- a visible final-mix limitation note when stems are unavailable.

#### `05_证据与说明`

- export ID and template version;
- source-generation bindings;
- measured/estimated/interpreted/reviewed legend;
- unresolved items;
- engine availability and versions;
- client-safe limitations;
- no secrets, absolute private paths, provider raw responses, or internal audit tokens.

## PDF contract

### Format

- A4 landscape by default;
- print background enabled;
- embedded CJK fonts;
- selectable/searchable text;
- document title, author, subject, keywords, and language metadata;
- page number and short project title in footer;
- bookmarks for major sections when supported;
- tagged PDF when the renderer supports it without layout regression.

### Page sequence

1. cover;
2. executive overview;
3. narrative structure and audio arc;
4. storyboard pages;
5. VO/on-screen-text timeline;
6. music/SFX/rhythm timeline;
7. evidence and limitations.

### Storyboard density

Default `client` density uses four shots per landscape page. This keeps frames and descriptions readable and may produce a longer document.

Optional `compact` density uses up to eight shots per page for internal production review. It is never the default client setting.

Pagination rules:

- keep shot image, identity, and first description block together;
- do not split a short shot block across pages;
- continue exceptionally long text on the next page with shot identity repeated;
- prevent orphan headings and single-row trailing pages when rebalancing is possible;
- do not crop text or reduce it below the typography floor;
- use a full-width continuation page when a VO or music note cannot fit safely.

## Automatic layout engine

Before rendering, calculate:

- frame aspect ratio and target box;
- estimated wrapped-line count for every text field;
- row/block height;
- page capacity by density;
- section break cost;
- continuation rows/pages;
- required font glyph set;
- expected image count and total media size.

The engine may choose from approved layout variants only. It must not invent ad hoc styles during a run.

The XLSX adapter has a separately measured capacity envelope of 3,200 shots
and 8,000 audio events. These limits are lower than the generic dataset limits
because openpyxl builds a styled workbook in memory. XLSX preflight fails
before rendering when either bound is exceeded, and the renderer independently
guards Excel's 1,048,576-row hard limit. Raising these values requires a new
memory/scale benchmark and template hash; it is not a documentation-only edit.

Approved variants:

- `client-landscape-4`;
- `compact-landscape-8`;
- `text-continuation`;
- `missing-frame`;
- `audio-timeline-wide`.

If content still cannot fit within approved constraints, generation fails with an actionable layout error and retains no partial current package.

## User settings

The Generate dialog exposes only stable choices:

- language: Chinese, English, or bilingual;
- density: client or compact;
- formats: Excel, PDF, or both;
- optional project subtitle;
- optional logo from a validated local PNG/JPEG;
- optional accent color with contrast validation;
- Save as version, off by default.

Settings are stored separately from source evidence and become part of the export receipt.

## File lifecycle

- generating replaces only `reports/client/current/` after all selected formats validate;
- failed generation leaves the previous current package untouched;
- stale current files remain visibly stale and professionally blocked until regenerated or deleted;
- Save as version copies the verified current package into one immutable export-ID directory;
- no autosave history, timestamp spam, or per-test output is written into a project;
- UI shows current size, saved-version size, and explicit delete actions;
- deletion is never automatic for explicit user versions.

## Test-output lifecycle

- unit and integration tests use process-scoped temporary directories;
- successful tests remove workbooks, PDFs, rendered PNGs, extracted frames, browser profiles, and font caches;
- failed tests may retain a bounded diagnostic directory only when the test runner explicitly requests it;
- CI uploads failure diagnostics only, with a short configured retention period;
- golden assets are minimal, reviewed, redistributable, hash-bound, and committed only when needed for regression comparison;
- private client media and client-specific exports are never test fixtures.

## Template verification

### Structural

- expected sheets and section order;
- exact shot and segment coverage;
- embedded-image count and bounds;
- no formulas, macros, external links, or private paths;
- deterministic ordering and template version;
- valid XLSX ZIP and PDF structure.

### Content

- no reviewed blank is replaced by machine text;
- no unsupported SFX, speaker, VO, music-title, or stem claim;
- confidence, source, and verification status accompany interpretations;
- draft/final wording matches readiness.

### Visual

Render representative small, medium, large, Chinese, English, bilingual, missing-frame, long-text, and no-audio fixtures. Verify:

- no overflow, clipping, overlap, distorted image, or unreadable text;
- CJK glyphs render rather than becoming blanks or tofu;
- minimum font size and contrast;
- balanced page breaks;
- headers/footers and page numbers;
- client and compact density snapshots;
- Excel-compatible and LibreOffice-compatible workbook previews;
- PDF raster previews at representative pages, not only page one.

### Acceptance

The template is release-ready only when the same frozen dataset produces matching content across Excel, HTML, and PDF, all visual regression fixtures pass, and no manual cell, page, font, or image adjustment is required after generation.
